# Architecture

One Next.js application and a PostgreSQL database serve browser, JSON API and MCP clients. Shared services under `src/server` own authorization and business rules. Render Free runs the web app and an embedded queue drain; local development can use a standalone worker. There is no paid hosted worker or filesystem dependency.

## Source to delivery

1. An allowlisted importer fetches real FDA records, normalizes whitelisted fields, validates dates and encrypts an immutable `DatasetSnapshot`. Provider uploads use the same storage contract. Public offers expose metadata and a fixed two-row/four-field preview only.
2. An external agent submits category-specific requirements through `discover_data`, or Gemini extracts browser requirements. Trove’s shared evaluator searches public metadata with PostgreSQL full-text ranking, checks matching private-row counts, fields, permitted use, freshness, ownership and budget, then selects complete lowest-cost coverage or returns gaps. It never silently relaxes a request. No external-agent call needs a Trove model key. Missing browser AI configuration/quota remains an error.
3. A quote pins source/version/hash, selected record indexes and fields, purpose, licence, freshness, delivery-cache hours, commission and exact USD total. It expires after five minutes. Provider edits create new versions and cannot mutate existing quotes.
4. Purchase creation serializes acquisitions by workspace, rejects already-owned or pending duplicate scopes, locks the quote and task budget, reserves only the exact total, and persists an idempotency key. The browser obtains genuine PayPal buyer approval. MCP cannot approve, capture or alter recipients.
5. The worker authorizes the order, prepares every approved dataset and validates the complete bundle before capture. Prepared results are encrypted. Authoritative completed capture then creates the entitlement, receipt, balanced ledger and seller payables in one transaction.
6. Reconciliation uses persisted payment identities after uncertain responses. It never retries a charge with a new identity. Refund completion revokes further access and reverses accounting. Submitted/paid payouts are flagged for separate recovery.

## Identity and isolation

Email/password or Google OpenID Connect registration creates a private user and workspace. Password accounts remain restricted until email ownership is proven. Six-digit codes are cryptographically random, keyed-hashed with a distinct domain and random nonce, browser-session-bound, valid for ten minutes and five attempts, and serialized per user for one-time consumption. Resends and guesses have separate shared hourly limits. Confirmation revokes pending sessions and tokens before issuing a new session. The browser can resume the pending step; API and MCP authentication reject unverified identities, including legacy agent tokens. Missing Gmail configuration or delivery errors never skip verification. Expired challenges are purged by maintenance.

Google uses PKCE, browser-bound single-use state, nonce and Google’s signed ID-token verification. Its verified matching email does not need a separate code. Existing email accounts require explicit authenticated linking; no automatic email-based account merge occurs. Google-only account closure requires a recent Google session. Scrypt passwords, hashed expiring session/agent tokens, cookie Origin checks, browser-only account/provider actions, atomic database rate limits and server ownership checks protect each boundary. Password recovery uses single-use hashed tokens and genuine HTTPS email; a successful reset also verifies ownership of that email and clears pending codes. Password change/reset revokes sessions and agent tokens. Account closure disables access, redacts profile details and retains accounting identities. See [credential setup](GOOGLE_AUTH_SETUP.md).

Provider onboarding is pending until an operator reviews identity, rights and payment routing. Public clients cannot self-approve or change payout recipients. Uploaded data remains encrypted and unlisted while pending. Declared publishing rights require actual operator review; a checkbox cannot prove a legal entitlement.

## Durable operations

PostgreSQL is authoritative for jobs, leases, budgets and financial state. Embedded timers improve latency only. Verified webhooks are persisted uniquely with an outbox job before acknowledgement; jobs reconcile external resources rather than applying event labels blindly. Protected hourly maintenance recovers work after restarts, imports sources daily and purges expired terminal results. Health checks never query the database.

Payment, fulfilment and settlement are separate states. Sandbox and live environments cannot operate on each other's purchases. Encrypted delivery caches default to 24 hours, pinned in the quote. Unrefunded purchase entitlements durably cover the original provider, canonical batch content, purpose, licence, fields and scoped record occurrences. Row/key reordering, retrieval dates and price-only changes do not invalidate ownership; actual batch content changes or expanded scope require a new quote. Cache expiry rebuilds the approved source subset without payment or ledger writes. Ownership derives from retained captured purchases and source snapshots, including historic purchases, rather than an agent’s memory. Mixed plans list reused sources separately; all-owned plans have zero total and cannot enter checkout. Separate prior purchases are not combined to invent a broader scope. Source snapshots and financial history are retained to preserve previously approved versions. Optional Elasticsearch contains public metadata only; database filtering rechecks visibility and current availability.

## Practical limits

Free hosting can sleep and scheduled jobs can be delayed. No uptime guarantee is implied. There is no stored wallet balance, escrow, reusable spending mandate or automatic split checkout. Live marketplace operation still requires merchant approval, provider contracts and operational policies. The current integration defaults to PayPal Sandbox; enabling live mode is an explicit configuration and business decision.
